# 근상 · 수민 모바일 청첩장

Canva로 제작된 모바일 청첩장을 정적 사이트로 미러링해 GitHub Pages로 서비스합니다.

- **라이브**: https://lyg2798.github.io/kmong-7500711/
- 페이지: `/`(커버) → `/main-page`(본문) → `/address-collection`(구 참석여부 페이지)
- `/main-page`의 **봉투(히어로)는 Canva 그대로**, 그 아래는 `custom/relayout.js`가 다시 그립니다
  (아래 "메인 페이지 레이아웃 교체" 참고). 참석여부는 본문 안에 들어왔고,
  `/address-collection`은 예전에 공유된 링크가 살아 있도록 그대로 둡니다(어디서도 링크하지 않음).

## 구조

| 파일/폴더 | 역할 |
|---|---|
| `index.html`, `main-page.html`, `address-collection.html` | 페이지 문서 (Pages의 `.html` 자동 매칭으로 `/main-page` 같은 확장자 없는 주소 서빙) |
| `_assets/` | 원본 자산 전체 (JS/CSS/폰트/이미지/영상/BGM) — 수정 금지 |
| `custom/` | 이 프로젝트에서 추가한 커스터마이즈 (아래 참고) |
| `_footer.html`, `_online.html` | 런타임이 fetch하는 `_footer`, `_online` 엔드포인트의 정적 스텁 |
| `.nojekyll` | Jekyll이 `_assets` 등 언더스코어 경로를 제외하는 것 방지 (삭제 금지) |

**원칙**: `_assets/`의 **내용은** 절대 건드리지 않습니다. 모든 변경은 `custom/`에 새 파일을
만들고 HTML 3개 문서에 태그 한 줄을 더하는 방식으로만 합니다. 원본 충실도를 지키고, 언제든
태그만 빼면 원본 그대로 돌아갈 수 있게 하기 위해서입니다.

유일한 예외가 **무손실에 가까운 재압축**입니다. 파일명·경로·픽셀 크기·포맷을 그대로 두고
용량만 줄이는 것이라 위 원칙이 지키려는 것(원본과 같은 화면, 되돌릴 수 있음)은 그대로입니다.
되돌리려면 `git checkout <이전 커밋> -- _assets/`.

## 원본 대비 수정 사항

### HTML 3개 문서 (`index` / `main-page` / `address-collection` 전부 동일하게)

1. `<base href="/kmong-7500711/">` — 서브패스 배포에서 자산 로딩·SPA 라우팅이 동작하기 위한 필수 수정
2. `og:image` URL을 이 도메인으로 교체 (카카오톡 등 공유 미리보기)
3. 참석여부(RSVP)는 **자체 폼으로 대체** — 본문 안의 폼은 `custom/relayout.js`, `/address-collection`
   페이지의 폼은 `custom/rsvp.js`가 담당합니다. **둘은 같은 Apps Script 웹앱에 같은 키·같은 저장값
   (`name`/`side`/`attend`/`count`/`meal`, 식사는 `O`/`X`)으로 보냅니다** — 수신처를 바꿀 때 두 파일의
   `RSVP_ENDPOINT`를 같이 고쳐야 합니다. 원래는 문서 끝 인라인 폴백 스크립트가 있었으나 `rsvp.js`로 옮기며 제거함.
4. 스크롤바 숨김 `<style>` (`scrollbar-width: none` + `::-webkit-scrollbar`) — 스크롤 자체는 그대로 동작
5. `custom/` 모듈을 불러오는 `<link>` / `<script defer>` 태그
6. BGM 노드를 **재생 경로가 하나만 남도록** 정리 (bootstrap JSON 안 2곳, 같은 노드가 두 번 등장)
   - `files[0].url` → `custom/bgm.mp4`
   - `hlsManifestUrl` **키 자체를 삭제**, `dashVideoFiles`·`dashAudioFiles` → 빈 배열
   - `durationSeconds` → 실제 음원 길이(255.894). 원래 값은 이 노드가 예전에 담고 있던 102초 영상의 길이였음

> **왜 대체 소스를 전부 지웠나 — 아이폰에서 음악이 안 나오던 원인**
> Safari는 HLS를 네이티브로 우선하는 유일한 엔진입니다. 부모 매니페스트
> (`_assets/video/7eb447….m3u`)는 미러링됐지만 **그 안이 참조하는 하위 매니페스트 5개는
> 애초에 캡처되지 않아 전부 404**입니다. 그래서 Safari는 부모를 받고 → 하위에서 실패 →
> `MEDIA_ERR_SRC_NOT_SUPPORTED` → 플레이어가 재생 버튼 대신 **다시하기 아이콘**을 띄웠습니다.
> `bgm.mp4`는 요청조차 하지 않습니다. Chrome은 HLS를 쓰지 않으므로 이 문제를 영영 잡을 수
> 없었습니다 — **미디어 관련 변경은 반드시 WebKit으로도 확인할 것**
> (`npx playwright install webkit` 후 headless로 실행하면 창이 뜨지 않습니다).
> 대체 소스를 지우면 원본 음원이 재생될 여지도 함께 사라집니다.

### 메인 페이지 레이아웃 교체 (2026-07-27)

클라이언트 요청: `/main-page`의 **봉투는 지금 그대로 두고, Invitation 섹션부터 아래로는
`anniversarymovie.kr/view/template02`의 레이아웃**으로. 문구·이름·장소 등 내용은 이 청첩장 것,
배경색과 톤도 이 청첩장 것(크림 2단 `rgb(255,250,244)` / `rgb(251,247,238)`, 잉크 `rgb(120,105,56)`).

`custom/relayout.js` + `custom/relayout.css`가 담당합니다. 섹션 순서는 템플릿을 따릅니다 —
INVITATION(영화 인용 + 인사말 + 혼주) / WEDDING DAY(날짜 + 10월 달력 + D-day) / GALLERY(대표 사진
\+ 썸네일 스트립 + 라이트박스) / LOCATION(식장 + 지도 + 지하철·주차 + 네이버·카카오·티맵 버튼) /
INFORMATION(스와이프 카드 2장) / 마음 전하실 곳(신랑측·신부측 계좌번호 펼치기 + 번호별 복사 버튼) /
RSVP(본문 내 폼) / 공유하기 / 맺음말.

**마음 전하실 곳은 계좌번호로 바뀌었습니다.** 원래 Canva 섹션에는 플레이스홀더 연락처
(`(123) 456-7890`, `hello@reallygreatsite.com`)가 남아 있었고, 그 자리에 클라이언트가 준 실제 계좌
4건(신랑 1 / 신부측 3)이 들어갔습니다. 값은 `custom/relayout.js`의 `HEART.groups`에 있습니다.
복사 버튼은 **은행명 없이 계좌번호만** 클립보드에 넣습니다 — 은행 앱 입력란에 그대로 붙일 수 있어야 하니까요.
카카오톡 인앱 브라우저에 `navigator.clipboard`가 없을 수 있어 `execCommand('copy')` 경로를 함께 둡니다.

**왜 Canva 섹션을 고치지 않고 다시 그렸나.** 그 섹션들은 문서가 아니라 섹션마다 하나씩 있는
절대배치 캔버스이고, 요소의 좌표는 런타임이 화면 폭마다 px로 다시 계산해 인라인으로 씁니다.
순서를 바꿀 흐름도, 다시 흐를 줄바꿈도 없고 모든 좌표가 런타임 소유입니다. 새 레이아웃을 일반
문서 흐름으로 옮긴 것이 반응형이 되는 유일한 방법이고, 어차피 그 섹션들은 전부 교체 대상이라
잃는 것이 없습니다.

**봉투는 손대지 않습니다.** 봉투 그림의 요소는 하나도 이동·크기변경·restyle하지 않습니다.
손댄 것은 두 가지뿐입니다 — **섹션 높이를 그림이 끝나는 지점까지 잘라낸 것**과, 바로 아래의
**레코드 잔재 제거**. 높이는 캔버스가 아니라 `<section>` 박스에만 걸고 `overflow:hidden`으로
자릅니다 — 캔버스 높이를 줄이면 `savethedate.js`가 %로 잡는 "Save the Date"가 움직입니다(아래 참고).

**재생 컨트롤(플레이어) 제거.** 레코드는 화면에서 사라졌지만 런타임은 그 근원인 영상 노드를
계속 들고 있고, 그 노드의 재생 컨트롤을 오버레이 레이어에 **레코드가 있던 자리(24×24, "Save the
Date" 위)** 에 계속 그립니다. 평소 `opacity:0`이라 폰에서는 안 보이지만 데스크톱에서 포인터가
그 위에 오면 ▐▐ 가 떠오릅니다. 그래서
`relayout.css`가 봉투 섹션의 `.QhExXw`(컨트롤 레이어)를 **아예 지우고**, `relayout.js`가 레코드의
세 서브트리(바이닐 gif / 영상 노드 / 곡선 "click to play")를 **자산·내용으로 식별해**
`opacity:0; pointer-events:none`(`data-cg-silent`)으로 만듭니다.
`display:none`이 아니라 **불투명도**인 것이 중요합니다 — `bgm.js`가 그 영상 노드의 `pause`를
음악에 미러링하고(섹션이 화면을 벗어날 때 오는 pause는 무시), 레이아웃에서 빼면 어떤 pause를
보게 되는지가 달라질 수 있습니다. 불투명도는 재생·교차관찰·레이아웃을 전혀 바꾸지 않고,
자손이 다시 선언해서 되돌릴 수도 없습니다.

검증(라이브 대비, 390 폭 `y<476` 크롭):
- 봉투 영역 픽셀 차이 **0.192%**, 최대 채널차 **18**. 차이가 8을 넘는 픽셀은 **0.002%**뿐이고
  전부 위의 "click to play" 잔상 자리(x219~265, y135~150)에 모여 있습니다. 레코드 잔재를
  제거하기 **직전까지 같은 영역은 0.000%**(최대 채널차 0)였으니, 이 차이는 그 잔상 하나입니다.
  라이브에 아주 흐리게 남아 있던 글자이고, 레코드가 없는 지금은 없어야 하는 것입니다.
  **다음 배포 뒤에는 이 기준선이 다시 0.000%가 됩니다.**
- "Save the Date" 위치 오차 **0.5px 미만**(320·360·390·412·430)
- 320~768 폭에서 히어로가 그림 끝 +2px에 정확히 잘림, 가로 오버플로 0
- 상호작용 전부 **Chromium·WebKit 양쪽 통과**, 커버에서 봉투 열기 → 새 본문 도착 → BGM
  재생·시계 진행까지 **WebKit 실측 통과**

### 지도 카카오맵 교체 + 티맵 버튼 (2026-07-27)

클라이언트 요청: LOCATION의 구글 지도를 **네이버 또는 카카오**로 바꾸고, **티맵으로
길안내를 여는 버튼**을 추가. JQ님이 카카오맵을 선택했습니다.

> **키가 필요합니다 — 이게 이 작업의 전부입니다.**
> 네이버와 카카오 **둘 다 키 없는 지도 임베드를 더 이상 제공하지 않습니다.** 네이버는 지도
> v5에서 "HTML 태그 복사"를 없앴고, 카카오의 퍼가기(roughmap)는 `map.kakao.com`에서 지도마다
> 손으로 발급받는 key가 필요한 데다 `document.write` 기반이라 로드 후 주입하는 이 구조에서는
> 쓸 수 없습니다. 남는 것은 **카카오맵 JavaScript SDK + 앱 키**뿐입니다.

키는 `custom/relayout.js`의 **`KAKAO_JS_KEY`**에 들어가 있습니다 (`b4ffe363…`).
**JavaScript 키는 원래 공개됩니다** — 지도를 그리는 모든 페이지의 스크립트 URL에 실려 나가므로
정적 사이트에서는 숨길 방법이 없습니다. 키를 지키는 것은 콘솔의 **도메인 목록**입니다:
거기 등록된 origin에서만 응답합니다.

> **이 키가 어느 앱에 있는지가 중요합니다.**
> 앱 **1467642 `jqerin-mobile-invitation`** (JQ님 본인 청첩장 앱) 안의 **`kmong-7500711`이라는
> 이름의 JavaScript 키**이고, `https://lyg2798.github.io`가 그 키의 SDK 도메인으로 등록돼 있습니다.
>
> 왜 이 프로젝트 전용 앱을 쓰지 않았나: **2026-07-21부터 카카오맵 무료 쿼터는 개발자 계정에서
> "첫 번째로 활성화한 앱" 하나에만** 나옵니다. 그 자리를 이미 저 앱이 차지하고 있어서, 새로 만든
> 앱(`kmong-7500711`, ID 1525161)은 **비즈월렛(결제수단)을 연결해야만** 카카오맵을 켤 수
> 있었습니다. 그래서 **기존 앱 안에 키만 하나 더** 만들었습니다 — **쿼터는 키가 아니라 앱 단위**로
> 세므로 무료 그대로이고, JQ님 청첩장의 기존 키·도메인은 건드리지 않습니다.
> 무료 한도는 **일일 카카오맵 30만 건 / 전체 API 월 300만 건**이라 청첩장 둘이 나눠 써도 무관합니다.

**앱과 지도 내용은 아무 상관이 없습니다.** 앱은 인증·과금 단위일 뿐이고, 어느 장소를 그릴지는
각 사이트 코드의 좌표(`VENUE_LAT`/`VENUE_LNG`)가 정합니다. 앱 이름이 하객에게 보이지도 않습니다
(앱 이름이 노출되는 건 카카오 로그인 동의화면·카카오톡 메시지 쪽이고, 지도 표시에는 그런 화면이 없습니다).

**주의**: 나중에 그 앱을 지우거나 도메인 목록에서 `https://lyg2798.github.io`를 빼면 이 청첩장
지도가 **조용히 구글 폴백으로 돌아갑니다**(화면은 안 깨집니다). 클라이언트 도메인으로 옮길 때도
그 도메인을 같은 키에 추가해야 합니다.

키가 비거나 거부되면 **기존 구글 임베드로 되돌아갑니다** — 지도 자리가 비는 일은 없습니다
(스크립트 `onerror` → `fallbackMap()`). 상태 확인은 이 한 줄:
```
curl -s -H "Referer: https://lyg2798.github.io/kmong-7500711/main-page" \
  "https://dapi.kakao.com/v2/maps/sdk.js?autoload=false&appkey=b4ffe3638aea0a379080b34510538b01" | head -c 120
```
자바스크립트가 돌아오면 정상, `domain mismatched`면 도메인이 빠진 것, `appKey(…) does not exist`면
키가 사라진 것입니다.

지도 동작:
- 좌표는 `VENUE_LAT` / `VENUE_LNG` = `37.5702334, 127.0087478` (WGS84). **여기서 지오코딩한 값이
  아니라 카카오가 그 장소에 쓰는 좌표**를 Places 검색으로 읽어 온 것입니다 — 그래야 마커가
  카카오가 호텔을 그리는 자리에 정확히 앉고, 티맵에도 그 호텔의 대표 지점이 넘어갑니다.
  (처음엔 OSM 건물 중심 `37.5703683, 127.0088222`를 썼는데 라이브에서 보니 약 15m 북쪽이었습니다.)
  지도·딥링크·티맵이 **전부 이 한 쌍**을 씁니다
- **지도는 고정입니다** (`draggable:false`, `setZoomable(false)`). 청첩장은 한 줄 스크롤이라
  움직이는 지도는 지나가려는 세로 스와이프를 삼킵니다. 대신 **지도 박스 전체가 카카오맵으로
  가는 링크**(`.cg-map-tap`)입니다 — 아래쪽 24px은 카카오 자체 로고·저작권이 눌리도록 비워 둡니다
- **박스는 정사각형**입니다(JQ 요청, 2026-07-27). `aspect-ratio`가 아니라
  `height:0` + `padding-bottom:100%`로 잡았습니다 — 그 속성을 모르는 브라우저에서 `aspect-ratio`의
  실패 모드는 **박스가 0으로 무너지는 것**이고, 하객은 어떤 버전인지 알 수 없는 인앱 브라우저로
  들어옵니다. `.cg-map-canvas`는 그래서 `position:absolute`로 패딩 박스를 채웁니다
- 마커 위에 식장 이름 라벨(`.cg-map-pin`)을 얹습니다. `CustomOverlay`의 `yAnchor`는 **콘텐츠
  높이의 배수**라서 `.cg-map-pin { height: 26px }`는 **고정값이어야 합니다** — 26을 바꾸면
  `yAnchor: 2.5`도 같이 바꿔야 합니다
- 지도는 `buildContent()`가 아니라 **마운트 후** `ensureMap()`에서 그립니다. 카카오 지도는
  생성되는 순간 컨테이너를 측정하는데, `buildContent()`는 문서에 붙기 전에 만들어집니다

**지도앱 줄은 카드 하나에 셀 셋**입니다(JQ 요청, 2026-07-27). 낱개 타일 셋이 아니라 "여기서
어디로 갈지"라는 **하나의 컨트롤**이라, 둥근 면 하나에 셀 사이만 실선으로 나눕니다. 배경은
카드(`.cg-maplinks`)가 갖고 셀은 투명이며, 구분선은 `box-shadow: inset`이라 **칼럼 폭을 넓히지
않고** 카드 바깥 모서리에도 생기지 않습니다. 아이콘과 라벨 사이는 flex `gap`이 아니라
`margin-top` 입니다 — 오래된 인앱 WebView가 flex gap을 배치하지 못합니다.

**아이콘은 여기서 그린 일반 지도 핀**이고, 각 서비스의 색으로만 칠했습니다
(`MAP_APPS[].tone` / `tones`, `pinSvg()`). **셋을 한눈에 구분해 주는 건 색**이고, 모양은 어느 회사
앱 아이콘의 복제가 아니라 일부러 평범한 핀입니다. 공식 앱 아이콘을 쓰시려면 각 사의 BI/브랜드
페이지에서 파일을 받아 `_assets`에 넣고 `pinSvg()` 자리를 `<img>`로 바꾸면 됩니다 — 상용 납품물이니
그 편이 안전합니다.

**티맵 버튼**은 `<a>`가 아니라 `<button>`입니다 — 어느 URL을 쓸지가 플랫폼마다 다르고
iOS는 타이머가 필요합니다(`openTmap()`).

| | 여는 것 | 앱이 없으면 |
|---|---|---|
| Android | `intent://route?goalname=…&goalx=…&goaly=…#Intent;scheme=tmap;package=com.skt.tmap.ku;…` | `S.browser_fallback_url` 로 **OS가 알아서** 플레이스토어 |

**iOS와 Android는 같은 세 값을 다른 이름으로 받습니다**(`rGoName/rGoX/rGoY` vs

이유는 "앱이 없으면 스토어"를 **URL 하나로** 표현할 수 있는 유일한 방법이기 때문입니다 —

### 공유하기를 실제 공유로 (2026-07-27)

클라이언트 요청: "공유하기 (링크 복사)"를 **진짜 공유 버튼**으로.
`navigator.share`(OS 공유 시트)를 쓰고, 시트가 없는 브라우저에서만 복사로 떨어집니다.

**넘기는 것은 `/main-page`가 아니라 커버(`./`)입니다.** 하객이 받아야 하는 건 봉투이지 그 안의
페이지가 아닙니다 — 커버가 청첩장이 열리고 음악이 시작되는 자리이고, 청첩장 자신의 제목과
미리보기 이미지를 가진 페이지이기도 합니다. URL은 문서의 `<base>`를 타도록 `<a>`로 풀어 냅니다
(맺음말의 "Return to the Invitation" 링크와 같은 방식).

> **같이 고친 것 — `/main-page`와 `/address-collection`의 `<title>`이 Canva 기본값이었습니다.**
> 각각 `Main Page`, `Address Collection`이라 **공유 미리보기 카드에 "Main Page"라고 뜨는 상태**였고
> 브라우저 탭에도 그렇게 보였습니다. 커버와 같은 `근상/수민 청첩장`으로 맞췄습니다(`<title>`과
> `og:title` 두 곳만). **같은 문자열이 bootstrap JSON 안에도 있는데 그건 Canva의 페이지 이름·라우팅
> 키(`"L":"main-page","O":"Main Page"`)라 건드리면 안 됩니다** — 정확히 두 군데만 치환했습니다.

동작 세부:
- `{ title, url }`만 넘깁니다. **`text`는 넣지 않습니다** — 공유 대상 앱 중에 텍스트만 가져가고
  링크를 버리는 것들이 있는데, 여기서는 링크가 전부입니다
- **시트를 닫은 것(`AbortError`)은 실패가 아닙니다.** 그때 몰래 복사하고 "복사되었습니다"를
  띄우면 방금 아니라고 한 것에 답하는 꼴이라, 아무것도 하지 않습니다. 그 외의 거부는 복사로 폴백
- 라벨은 **시트가 있으면 `공유하기`, 없으면 `공유하기 (링크 복사)`**. 못 하는 일을 약속하는 것보다
  하는 일을 말하는 편이 낫습니다. (WebKit은 헤드리스에서도 `navigator.share`를 실제로 가지고
  있습니다 — 검사에서 "시트 없음"을 재현하려면 프로토타입을 가려야 합니다)

검증 — `reference/tools/share_test.js` (`node share_test.js <base> [engine]`), **Chromium·WebKit 통과**:
시트가 열리는지·커버 URL과 제목이 넘어가는지·`text`가 없는지·몰래 복사하지 않는지 / 닫았을 때

- **캔버스 자식 요소의 `id`는 로드마다 바뀝니다.** `._mXnjA > div`들의 `id`(`LB…`)는 같은 요소인데도

  쓰지 않고 `data-cg-hidden` 속성만 붙이고, 숨기는 일은 `relayout.css`가 합니다 — 런타임이
  몇 번을 다시 쓰든 무관해집니다. 높이도 마찬가지로 `--cg-hero-h` 커스텀 속성으로 넘깁니다.
- **섹션을 짧게 자를 때 캔버스 높이를 건드리지 마세요.** `savethedate.js`는 "Save the Date"를
  캔버스 높이의 %로 배치하고, 그 위치는 여러 번 손으로 맞춘 값입니다. 자르기는 `<section>`에만
  걸고(`height` + `overflow:hidden`) 캔버스는 Canva가 준 높이를 그대로 두어야 안 움직입니다.
- **그래도 `savethedate.js`의 세로 nudge는 한 번 바뀌었습니다: `1.30%` → `1.470%`.** 원래
  1.30%는 `invitation.js`가 인사말을 넣으면서 캔버스를 늘려 놓은 높이 기준이었습니다(390 폭에서
  +128px). 그 모듈이 빠지자 같은 %가 1.7px 아래로 떨어졌고, 1.470%가 **지금 캔버스에서 같은
  픽셀 오프셋**입니다(320·390·430에서 오차 0.15px 미만). 캔버스 높이에 영향을 주는 변경을 하면
  이 값을 다시 계산해야 합니다 — 판정은 라이브와의 봉투 픽셀 비교로(`reference/tools/hero_visdiff.js`).
- **`hideRecord`의 스윕은 믿을 수 없습니다 — 음악이 재생 중이면 겨냥할 버튼이 없습니다.**
  스윕은 `button[aria-label="재생"]`의 중심에서 `elementsFromPoint`를 뜨는데, 런타임은 영상이
  재생 중이면 그 버튼을 `display:none`으로 두고 `일시 중지` 버튼을 대신 보여줍니다. 폭 0인
  버튼은 루프에서 건너뛰므로 **스윕이 아예 돌지 않고** 레코드가 살아남습니다(라이브에서도
  "click to play" 글자가 흐리게 남아 있었습니다). `relayout.js`는 같은 제거를 **노드의 성질로**
  다시 씁니다 — 바이닐 gif/포스터 파일 해시, `<video>`의 존재, "click to play" 문자열.
- **`hideRecord`는 재생버튼 좌표에 있는 좁은 요소를 전부 숨깁니다.** 섹션을 자르면 그 좌표가
  새로 그린 본문 위에 떨어질 수 있어서, 달력 칸·캐러셀 점·화살표가 사라질 수 있습니다.
  `#cg-relayout` 안쪽은 예외로 두었습니다(`savethedate.js`).
- **`.KYQZFA`와 그 부모 래퍼는 뷰포트 높이로 늘어납니다.** 섹션을 숨긴 뒤 둘을 `height:auto`로
  풀지 않으면 봉투와 새 본문 사이에 **화면 한 칸(844px)짜리 공백**이 남습니다.
- **새로 그린 섹션도 `<section>` 태그입니다.** "히어로가 아닌 섹션을 전부 숨긴다"는 판정에
  자기 자신이 걸려서 새 본문이 통째로 사라진 적이 있습니다 — `#cg-relayout` 안쪽은 제외합니다.
- **Canva 폰트 중 한글 전체를 가진 것은 `_assets/fonts/77776149…woff` 하나입니다**(11,172자).
  `a445cd2d…`(제목 세리프)·`01b954d1…`(원래 인사말 폰트)·`8461fcb6…`는 **라틴 전용**이고
  `b5494f0d…`는 137자 부분집합입니다. 새 한글 문구를 라틴 전용 패밀리로 쓰면 조용히 시스템
  폰트로 폴백합니다 — 지금 라이브의 인사말이 실제로 그 상태였습니다.
- "이미 내가 적용한 값인가"를 판정할 때는 **반드시 숫자로 비교**하세요(epsilon 사용).
  `transform`/`height` 문자열을 비교하면 브라우저가 값을 재직렬화하기 때문에 방금 내가 쓴 값도
  "내 것이 아님"으로 판정되어 보정이 무한 누적됩니다 (768px 폭에서 100만px 밀림이 실제로 발생).
- **소리는 절대 영상 노드에 태우지 마세요.** WebKit은 화면 밖 영상의 디코딩을 억제하는데,
  같은 파이프라인에 묶인 오디오까지 함께 느려집니다. 멈추는 게 아니라 **뒤처지는** 것이라
  `pause` 이벤트가 하나도 없는데도 소리가 끊겨 들립니다. 9초 스크롤 실측: Chromium은 벽시계와
  오차 0인데 WebKit은 **1440ms 손실**. iOS는 모든 브라우저가 WebKit이라 Safari·Chrome·
  카카오톡 인앱이 전부 해당합니다. 그래서 음악은 `<audio>`로 옮겼습니다.
  **미디어 변경 후에는 두 엔진 모두에서 "벽시계 대비 오디오 진행"을 재 보세요** — 화면만
  봐서는 알 수 없습니다.
- **커버가 "안 열린다"는 제보는 대부분 밀랍 씰입니다.** Canva는 "Open the invitation"
  타깃을 글자 단위 `<a href="#page-1">` 31개 + 뒤에 깔린 큰 것 1개로 만듭니다. 겉보기엔
  봉투 전체가 하나의 버튼 같지만 실제 히트 테스트를 뜨면 한가운데에 **가로 35px 세로 22px
  짜리 구멍**이 있고, 그 자리가 정확히 봉투 한복판의 밀랍 씰입니다. 봉투에서 "여기를 눌러라"
  라고 말하는 유일한 그림이 씰인데, 그걸 누르면 아무 일도 일어나지 않습니다. 손님 입장에서는
  청첩장이 안 열린 것과 구분이 안 됩니다. 전 폭(320/360/390/412/430) 실측으로 재현됐고
  `custom/cover.js`가 봉투 안쪽 탭을 앵커로 넘겨서 막았습니다.
  **커버를 건드리면 가운데를 눌러보고 확인하세요. 화면만 봐서는 절대 안 보입니다.**
- **레코드(LP) 제거가 어려웠던 이유 — 겹친 서브트리 + `visibility` 재선언.** 레코드는 한 요소가
  아니라 같은 자리에 겹친 여러 Canva 서브트리(디스크 gif / 곡선 "CLICK TO PLAY" / 재생 삼각형)이고,
  자식이 `visibility:visible`을 다시 선언해서 **부모에 `visibility:hidden`을 줘도 안 사라집니다.**
  `display:none`을 그 자리(재생버튼 중심)의 **요소 스택에서 폭<110짜리에 전부** 걸어야 깨끗이 지워집니다
  (`savethedate.js`의 `hideRecord`). 폭 상한을 안 두면 뒤의 콜라주 사진까지 지워집니다.
- **캔바 요소의 `font-size`는 스케일 이전 값입니다.** 원본에서 "Save the Date"의 계산된 `font-size`는
  77px이지만 실제로는 22px로 보입니다 — Canva 캔버스가 transform:scale로 줄이기 때문. 우리 요소는
  **스케일 없는 캔버스에 직접 넣으므로 그 77px를 그대로 쓰면 3배 크게** 나옵니다. **보이는 크기**(vw)로
  맞추세요. 폰트·색·문구·위치는 원본 Canva 사이트에서 그대로 떠 왔습니다(`savethedate.woff`).
- **참석여부(RSVP)는 자체 폼 → 구글 시트입니다.** `custom/relayout.js`(본문 폼)와
  `custom/rsvp.js`(`/address-collection` 폼) 상단의 `RSVP_ENDPOINT`가 같은 Google Apps Script
  웹앱 URL이고, 그 스크립트(`doPost`)가 지정된 구글 시트에 한 줄씩 append합니다.
  - **응답 수신처(구글 시트)를 바꾸려면**: 그 시트의 `확장 프로그램 → Apps Script`에 `doPost`를
    붙이고 `배포 → 웹 앱(실행: 나 / 액세스: 모든 사용자)` 후 나온 `.../exec` URL을 **두 파일의**
    `RSVP_ENDPOINT`에 교체. 현재는 JQ 개인 시트에 임시 연결(클라이언트 계정으로 이관 예정).
  - **제출은 `fetch(..., {mode:'no-cors'})`** — 응답을 읽을 수 없으므로(불투명) 성공은 낙관적으로 처리.
    Apps Script는 POST를 받으면 `302 → script.googleusercontent.com/macros/echo`로 넘기는데
    **이 302 자체가 doPost 실행 완료의 신호**입니다(접근 거부면 로그인으로 감). `curl`로 확인할 때
    `-L`로 리디렉션을 따라가면 echo 토큰이 한 번 쓰고 버려져 405가 뜨지만 **허상**이니,
    `-o /dev/null -w %{http_code}` 로 **초기 302만** 보세요. 최종 판정은 시트에 줄이 쌓였는지로.
- **미디어 `preload`는 커버의 대기시간입니다.** `bgm.m4a`는 5.9MB인데 `preload='auto'`면
  손님이 봉투를 누르기도 전에 전부 내려받습니다. 커버까지 받는 12MB의 절반이 아직 듣겠다고
  하지도 않은 음악이었습니다. `'metadata'`로 두면 헤더만 받고 재생 시점에 스트리밍합니다.
- **섹션 높이를 바꾸면 `.QhExXw` 오버레이 높이도 같이 바꿔야 합니다.** Canva는 영상 재생 컨트롤을
  캔버스와 별개인 이 레이어에 그리는데, 이 레이어는 섹션 **아래쪽**에 붙어 있고 높이가 캔버스와
  같을 때만 컨트롤이 제 그림 위에 놓입니다. 캔버스만 N만큼 키우면 그 섹션의 모든 컨트롤이 N만큼
  아래로 밀립니다 (LP의 재생 버튼이 아래 사진 위에 떠 있던 원인).

파일 수정 → 로컬 확인 → `main`에 push → GitHub Pages가 자동 재배포 (1~2분).
푸시 권한: `lyg2798` 계정 (`gh auth switch --user lyg2798`).

로컬 확인은 그냥 파일을 열면 안 되고, **서브패스(`/kmong-7500711/`)와 확장자 없는 주소**를
GitHub Pages와 똑같이 처리하는 서버로 띄워야 합니다. 이 둘 중 하나라도 다르면 `<base href>`
때문에 로컬에서만 백지가 되거나, 반대로 로컬에서만 멀쩡해 보입니다.
(작업 폴더의 `reference/tools/pages_server.py`가 이 동작을 재현합니다.)

```bash

# → http://127.0.0.1:8480/kmong-7500711/
```

배포 확인:

```bash

```
